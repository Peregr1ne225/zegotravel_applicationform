## Supabase Forms API

The `/api/form` route uses the Supabase JavaScript client and your `public.forms` table. Set `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` in `.env.local` from your Supabase project's API settings. The route accepts the columns in your forms schema directly; `id` is generated by the database. Since the table columns are `NOT NULL`, POST requests must include every other column. Use valid enum values for `home_type`, `military`, `marital`, and `sex`, and arrays for `sibling_member`, `education`, and `job`.

The API supports:

| Method | Request | Result |
| --- | --- | --- |
| `GET` | `/api/form` | List rows |
| `GET` | `/api/form?id=<id>` | Get a row |
| `POST` | `/api/form` with all non-id column values | Insert a row |
| `PATCH` | `/api/form?id=<id>` with `{"position":"Designer"}` | Update a row |
| `DELETE` | `/api/form?id=<id>` | Delete a row |

Send JSON with `Content-Type: application/json`. Supabase grants and Row Level Security apply to these requests; keep the publishable key in use and configure policies for your intended access. Do not use a service-role key in client-visible variables.
